# Non-functional & Security Requirements

状態: Phase 0 初期案。性能目標の数値はPhase 1ベンチマークで確定する。

## NFR-01 実行環境・移植性

- 対象はmacOSのローカル起動。Apple SiliconのMacBook Airを最優先。
- ローカルKindle DBの取得はアプリバージョン依存として切り離す。
- Chromium/ブラウザ操作はPoCの合格後だけ有効化。ブラウザ操作ができなくてもアプリの台帳/Drive機能は使える。
- SQLiteは単一プロセス運用。同期多重起動は禁止。クラウドサーバーや常駐デーモンは必須にしない。

## NFR-02 情報保護

- Amazonパスワード、多要素認証情報、ブラウザCookieやログインセッションを独自収集・保存しない。
- Google OAuth refresh tokenはmacOS KeychainなどOSの資格情報ストアへ保存。SQLiteや設定ファイル、ログ、Issue、テストフィクスチャに平文で入れない。
- Google Driveはまず drive.file を採用し、アプリが作成またはユーザーが選択して許可した範囲で操作。
- 既存ファイルを全Driveから検索するには追加スコープが必要になる可能性をユーザーへ示す。最小権限を優先し、広範なDriveスコープはデフォルトで要求しない。
- Amazonアクセスは本人による通常ログインを基本にし、CAPTCHA/二段階認証/アクセス制限の迂回はしない。
- 不要なユーザー情報を保存しない。書籍一覧も私的データであり、GitHubリポジトリやCIログに含めない。
- ブラウザやGoogle DriveのセッションURL・認証エラー本文などはログに出さない。
- 出力PDF・EPUBは個人利用の非公開フォルダに保存し、Driveの共有設定を自動変更しない。

## NFR-03 権利・利用条件

- 公式にダウンロード可能なコンテンツのみを自動取得対象とする。
- Amazon/KDP公表仕様はDRMフリーの正規購入者に対するダウンロードを認める一方、全ストア/全書籍/全アカウントで一括取得可能とは限らない。
- 国内の適用規約、著作権法、公式ブラウザ操作に関する禁止事項はPoCで確認し、結論に根拠URLと確認日を記録する。
- 法的適否を自動判断する仕様ではない。規約適合性が確認できない手段は本番に含めない。
- 旧スクリーンショットベースのconverterは通常同期から無効化し、DRM付き書籍を無理に取得するフォールバックにしない。

## NFR-04 耐障害性/データ安全

- 単一障害でSQLite台帳または既存Drive成果物を消さない。削除・上書きは明示操作・承認が必要。
- SQLiteへはトランザクション単位で保存、migrationをテスト。バックアップにはSQLite Backup APIを使用。
- Driveへの新規アップロードは予約fileIdと成果物sha256を先に永続化する。
- 通信断、429/5xx、一時的なDriveエラーだけを指数バックオフ+ジッタ付きでリトライ（回数上限あり）。
- 403の権限エラー、401の失効、購入未確認、照合ハッシュ不一致は自動リトライしない。原因に応じ再認証/手動判断が必要。
- 取得元スキャンの失敗時は「0件」として扱わない。部分成功を別状態で返す。
- Drive fileId不可視は削除確定と異なる。復旧手順で一覧再取得・権限検査。

## NFR-05 成果物品質とリソース

- PDFはページ数>0、パーサが開けること、暗号化や破損の有無、サイズ・ハッシュを検証。
- EPUBは構造、manifest、必須リソース、バイト列を検証。変換できない複雑なレイアウトは変換保留とし原本は保持。
- PDF・EPUBの原本を勝手に置換せず、変換結果・OCR結果を別成果物として保持する。
- 画像全ページの同時メモリ保持を避ける。ストリーミング/逐次変換などを採用。
- 大きなファイルはDrive resumable upload。ローカルのディスク残量を事前チェック。
- 性能SLOはPoCで1,000冊のダミー書籍照合と1GB級ファイルの処理を測り定義する。現時点で秒数を確約しない。

## NFR-06 可観測性・運用

- book_id、run_id、task_id、error_code、処理時間、再試行回数、source_healthを構造化ログに記録。
- デフォルトログにAmazonの画面内容・PDF本文・個人情報・認証情報を入れない。
- UIから安全な診断情報をコピー可能にする。エクスポート時に秘密情報が含まれないようサニタイズ。
- 書籍/成果物とログの保持期間はユーザーが設定可能にする。診断ログの初期値はローテーションあり。
- ローカルDBバックアップ・復元機能を用意し、破損とマイグレーション失敗時に安全停止。

## NFR-07 開発品質

- Pythonのdomain/application層はLinux GitHub Actionsでテスト可能。QuartzやAppleScriptをトップレベル依存させない。
- ruff・pytest・型検査の候補をPhase 0.5で検討。
- 重要なドメイン状態遷移、冪等性、障害注入、DB migrationを自動テスト。
- GitHubのmainにはPR経由で変更し、レビュー/CIを実施する。
