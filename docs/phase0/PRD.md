# PRD — Kindle Library Sync v0.3

更新: 2026-10-13 / ステータス: 設計案・PoC条件付き

## 1. 目的と対象

ユーザーはmacOSアプリの「同期開始」を押す。アプリは書籍台帳、Kindle for Macで認識される候補、利用者がアクセス可能なAmazon公式購入情報、Drive管理対象ファイルの差分を検出する。確認済み購入書籍について公式ファイルを利用できる場合は、取得（自動化はPoC通過時のみ）・検証・必要なPDF変換・Drive同期を実施する。不可・未確認ならその理由を台帳に残す。

### 対象
- 同一Amazonストア上の購入済みKindle電子書籍。0円で購入した電子書籍を含む。
- macOS（初期対象はApple SiliconのMacBook Air）、Google Drive個人アカウント。
- 一度に実行する同期は1件。書籍処理は逐次。
- Amazonの公式に提供されるEPUB/PDF、そこから作成するPDF。

### 対象外
- Kindle Unlimited / Prime Reading借用、サンプル、返品後に権利がない書籍。
- DRM解除、コピー制限・CAPTCHA・認証・レート制限の迂回。
- 読書画面の全ページ自動キャプチャを通常同期の取得手段にすること。
- クラウド常駐、購入直後の自動検知、複数端末の同期、電子書籍の再配布。
- Amazonアカウントにある全購入本が必ず検出・ダウンロードできるという保証。

### 「同期済み」の定義
特定書籍の対象成果物がDriveで再取得可能なfileIdに紐づき、リモート側に同じバイト列が保存されたことを検証済み。蔵書全体が「全部PDF化済み」であるとは言わない。DRM非対応/不明は「取得保留/要確認」であり処理失敗ではない。

## 3. 同期時のユーザーフロー

### UF-01 初回セットアップ
1. 環境診断（macOS/Kindleの導入/DB読み取り/OAuth・PDFツール）。
2. Google OAuth認証、アプリ管理フォルダの新規作成または選択（スコープ不足時は導線提示）。
3. Kindle候補スキャン・購入判定の確認。
4. Driveの既存PDF/EPUBは**アクセス可能な範囲だけ**照合。ユーザー選択で対象を追加。
5. 対象件数・未確認件数・取得保留件数・推定対象ファイル数を提示。
6. 初回の一括処理計画を確認した上で実行。

### UF-02 通常同期
1. 同期開始（ローカル多重実行を禁止）。
2. 認証とネットワーク状態を確認。各ソースの取得は**成功/部分成功/失敗**を区別。
3. 出典付き観測データと前回台帳を突合。ASIN欠損や同名異ASINは自動統合しない。
4. Drive fileId/メタデータ/ハッシュを照合し、同期計画を作成。
5. 事前承認済みの非破壊処理を順次実施。初回・大量処理・権限変更・既存ファイル上書きは確認を求める。
6. 実行結果は成功/スキップ/取得保留/要確認/失敗の内訳と次の必要操作を表示。

### UF-03 公式DL
- ローカル/ブラウザで正規の購入者本人として利用可能なファイル取得を検討する。
- ブラウザ自動化は技術面と規約面の両方に合格した場合にのみ有効にする。
- 非対応は DEFERRED_UNAVAILABLE、判断不可は NEEDS_REVIEW。無理に取得しない。
- 手動ダウンロードが必要ならアプリは安全な操作案内を表示。手元の**公式取得済み**ファイルだけを取り込む。

### UF-04 再開
中断後にローカル成果物・Drive実体を確認し、完了した工程を再実行せず未完了部分を再開する。

## 4. 差分ルール

| ケース | アクション |
|---|---|
| 検出されたが購入未確認 | 台帳に記録、公式DL処理しない |
| 新規購入確認済み、公式ファイル取得可 | 取得計画に追加 |
| 公式DL非対応 | 取得保留、エラーにはしない |
| 公式DL不明 | 調査待ち、非対応とは断言しない |
| 確認済みローカル成果物がありDrive未保存 | アップロード計画 |
| Driveに同一成果物あり | スキップ |
| 同名で異なるASIN/ハッシュ | 自動置換せず不整合として表示 |
| DriveのfileIdにアクセス不可 | 削除とみなさず再認証/再照合待ち |
| Kindle候補が消失 | 検出元が欠落した旨のみ記録。削除/返品と断定しない |
| Amazon権利確認に失敗 | 以前の購入根拠を抹消しない。今回の検証不能を表示 |

## 5. 基本受け入れ条件（詳細はTEST_STRATEGY.md）
- AC-01 同じデータで連続2回同期してもDrive上の重複が0件。
- AC-02 購入済み1冊追加で台帳に1件追加、既存書籍は変化なし。
- AC-03 KU/サンプル/判定不能の候補を取得対象と誤認しない。
- AC-04 DRMフリー公式DL非対応なら台帳に取得保留として残す。
- AC-05 ローカルPDF/EPUBが不完全・破損ならアップロードを拒否。
- AC-06 アップロード成功直後のプロセス強制終了から復旧できる。
- AC-07 Drive改名・移動はfileIdで追跡。削除は手動承認なしには行わない。
- AC-08 Google権限失効やAmazon認証切れで秘密情報漏えいなく安全に停止。
- AC-09 一部書籍の失敗で全体を停止せず、件数・理由を表示。
- AC-10 未取得・保留・要確認を「すべて同期済み」と表示しない。

## 6. 依存する調査
購入済み全件の網羅性・Amazonでの公式DLの操作条件・ブラウザ自動化の規約適合・Drive移行権限の可否は未検証。POC_PLAN.mdのGo/No-Go判定後に本仕様の該当箇所を確定する。
