# Phase 1 PoC Plan / Codex Research Backlog

更新: 2026-10-13 / 状態: 未実施。**この文書は実機調査の設計であり、技術的成功を保証しない**。

## 共通ルール

- 最初はread-onlyの実地調査。Amazonアカウントに対する書き込み/自動購入/大量リクエストを行わない。
- 実際のKindle DB、Cookie、OAuth token、購入履歴の生データ、PDF/EPUB本文をGitHubやIssueに貼らない。
- 調査ごとに環境（macOS/Kindle/ブラウザのバージョン、ストア地域）・操作手順・再現性・根拠・失敗例を記録する。
- ユーザーのMacへの権限付与やAmazonへのログインが必要な項目は**USER_ACTION_REQUIRED**として切り分け、Codexが勝手に認証を回避しない。
- 調査結果は可/一部可/不可/判断不可を分類し、代替案を必ず報告する。

## SPIKE-01 KindleローカルDBの蔵書認識

**問い**: 現行Kindle for MacはどのDB/スキーマを使い、何冊のASIN・タイトル・購入日が得られるか。
手順: 先行例 listKindleBooks2 のコード/対応バージョン調査→macOS版DBに読み取り専用でアクセス→データ型/件数/ASIN NULL率/書籍種別を匿名集計→機能をAdapter PoC化。
検証: 0円購入、通常購入、KU、サンプル、辞書、同名異版、未DLの購入本。
成果: フィールド対応表、Mac/Kindleバージョン、取得できないケース、候補の網羅率。
**Go条件**: DBを変更せず再現可能に取得でき、購入未確認を安全に区別できる。全購入の網羅率は数値を記録し、閾値は実測後判断。
代替: 手動CSVインポート/ブラウザで購入済み一覧確認。

## SPIKE-02 Amazon購入履歴の網羅性と購入証跡

**問い**: 利用者本人が確認できる公式UI/エクスポートに、購入済みKindle本の全件・0円購入・返品を区別する情報があるか。
手順: Amazon公式「コンテンツと端末の管理」等の画面と利用規約を確認→購入本/借用本/サンプルの分離を検証→ASIN照合精度を測る→APIの公開・非公開/安定性を区別。
成果: Sourceごとの購入根拠の強弱、手動フォールバック、網羅率、未確認ケース。
**Go条件**: 取得元の性質が判明し、購入と非購入の誤分類を最小化できる。未確認はVERIFIEDにしない。

## SPIKE-03 公式ダウンロードのブラウザ操作

**問い**: Amazonが公式提供するDRMフリー書籍のEPUB/PDFを、利用条件に反しない範囲でユーザー本人のブラウザから安全にダウンロードできるか。
手順:
1. Amazon KDP公式仕様とAmazon.co.jpの適用規約/画面を照合。
2. 本人がログイン済みの通常ブラウザから、少数の公式DL可能な書籍について手動操作を記録。
3. 許可範囲が明確な場合だけ自動操作のPoCを試す（認証/二段階/CAPTCHAを迂回しない）。
4. 書籍の同一性、取得形式、途中失敗、アカウント切替、レート制限を評価。
5. 取得可能→不可へ変化したケースを台帳へ反映する検証。

**Go条件（すべて必要）**: 公式画面で再現可能、同一性検証可能、認証秘密情報を収集しない、利用規約等の適合性が確認できる、失敗時に安全停止。
**No-Go時**: 手動DLの案内とファイル取り込み。DRM付き本は取得保留。

## SPIKE-04 Drive権限と冪等性

**問い**: drive.file + user selectionで希望する管理フォルダと既存ファイルをどこまで照合できるか。
検証: OAuth新規/失効、フォルダ新規作成/Picker選択、既存ファイル、リネーム/移動、appProperties、files.generateIds、409競合、途中終了、sha256Checksum・md5Checksumが欠ける場合。
**Go条件**: 無断削除/上書きなし、同一処理2回で新規追加0件、クラッシュ復旧後も重複0件。スコープの不足と代替操作を記録。

## SPIKE-05 PDF/EPUB品質・資源

**問い**: 日本語のEPUB原本から、現実的なメモリ/時間で検索可能なPDFが作れるか。
検証: リフロー・固定レイアウト・図表・縦書き・画像主体、PDF変換/文字化け/フォント/レイアウトの目視比較、OCR必要判定、ファイル破損、サイズ測定。
**Go条件**: サポート対象形式と非対応形式を明文化し、変換失敗で元ファイルを損なわない。
代替: 原本EPUBのみ同期し、PDF変換保留。

## SPIKE-06 既存converter/CIの分離

**問い**: macOS専用Quartz依存、Flet、OCRmyPDFをLinux上のドメインテストから分離できるか。
検証: importerテスト、dependency injection、Fake DriveとFake Kindle、低メモリPDF生成、既存4件テストの維持/見直し。
**Go条件**: Linux上でdomain/application層のテストが実行可能。Mac固有テストは別に継続。

## 検証マトリクス（匿名化結果のみ報告）

対象例: 有料購入/0円購入、KU借用、Prime Reading、サンプル、返品、同名別ASIN、日英書籍、DRM-free/DRM、PDF/EPUB片方だけ、コミック、複数アカウント/ストア（後者は将来対応のリスク検証）。
