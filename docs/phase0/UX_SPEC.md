# UX Specification — 手動同期型

更新: 2026-10-13 / 状態: Phase 0の基本UI契約。詳細ビジュアル実装はPhase 3。

## UX原則

1. **通常は「同期開始」1回**。最初の認証・フォルダ選択や権限変更では追加操作を求める。
2. 情報源が不完全でも「全蔵書同期済み」と誤認させない。
3. 書籍の「購入状態」「取得可否」「クラウド保存」を分けて表示する。
4. 取得保留は失敗扱いにしない。アクション可能なエラーに修正・再試行の導線を出す。
5. 無断の削除・上書き・同名ファイルへの自動上書きは一切行わない。
6. Macのアクセシビリティ・画面収録権限は通常同期で要求しない（旧キャプチャは独立）。

## 画面と情報設計

### U-01 初回ウィザード
- Step 1 環境診断: macOS/Kindle/ローカルDB/変換ツールの準備可否。
- Step 2 Drive接続: OAuthと管理フォルダ選択・作成。drive.file権限で見えない既存ファイルの説明。
- Step 3 購入本スキャン: 認識候補件数、購入確認済み、未確認、除外。疑義ありは手動承認保留。
- Step 4 既存ファイル紐付け: ユーザー選択範囲で検索。ファイル名だけの推測一致は確認必須。
- Step 5 初回同期計画: 対象書籍、推定ファイル数、権限条件、取り込み待ち、取得保留。
- Step 6 明示的な「初回同期開始」。

### U-02 ダッシュボード
- 最上部: 同期開始ボタン、最終実行時刻、データソース健康状態（Kindle/Amazon/Driveそれぞれ成功・不完全・未確認）。
- 件数カード: 購入確認済み、同期済み、取得保留、要確認、失敗、今回新規検出。
- 主導線: 書籍一覧・履歴・設定。保留理由が開けること。
- 「同期済み」は書籍台帳全体の存在確認とは独立。例: 「検出された購入確認済み120冊のうちPDF同期済み75冊 / 取得保留20冊 / 要確認25冊」。
- 完了時に通知: 登録X、新規保存Y、重複スキップZ、取得保留W、失敗E。
- Google DriveとAmazonがオフラインの場合は「最新の差分を確認できません」と表示。0件を成功と誤表示しない。

### U-03 書籍一覧/詳細
列: タイトル、著者、ASIN（短縮表示可）、購入状態、取得可否、Drive同期状態、最終更新、アクション。
フィルタ: 新着、同期済み、未同期、取得保留、要確認、失敗。検索: タイトル/著者/ASIN。
書籍詳細: ASINとストア、購入証拠の種類・時刻、最後の確認結果、利用可能な形式、ローカル成果物、Drive fileId/リンク、失敗理由と個別再試行。
状態別アクション:
- 購入未確認: Amazon側確認案内、購入証跡の手動確認。
- 取得可: 公式DL起動または手動DLガイド。PoC通過時のみ自動取得を表示。
- 取得保留: 理由と最終判定時刻。強制キャプチャ/DRM回避への誘導はしない。
- アップロード失敗: 再試行。
- Driveで見えない: アクセス権修復/再照合（削除扱いにしない）。

### U-04 同期結果/履歴
ジョブ進捗: 現在の書籍、工程、処理済み/総対象、件数ベース進捗。総ページ数や経過推定が不明なら不明と表示。
- 一時停止/キャンセルは安全な工程境界で受理。急停止後は再起動時に整合性再確認。
- 完了・一部失敗・失敗・キャンセルを区別。
- タスク詳細ログは人間向けの日本語理由と内部error_codeの両方を持つ。
- 再試行ボタンは安全なタスクのみ。購入未確認、権限不明、ハッシュ不一致は自動再試行しない。

### U-05 設定
- Googleアカウント接続状態と管理フォルダ、OAuth権限の再承認。
- 公式ダウンロード機能（実験フラグ、初期OFF）、手動ダウンロード案内。
- ファイル命名テンプレート（ASIN_タイトル）、EPUB原本の保持、OCR設定、ローカル一時ファイルの扱い。
- 診断ログの表示/削除、DBバックアップと復元、エクスポート。
- 「Drive全体を検索できない可能性がある」の説明とPicker導線。

## キーフロー

### 通常の1クリック同期
アプリ起動→同期開始→新着検出/Drive照合→安全な取得・アップロード→結果。
ただしブラウザDLが不可、Amazon認証要、購入状態不明なら個別で「操作待ち」として保留する。

### DL自動化が認められなかった場合
同期ボタンで書誌/Driveの差分まで自動。公式ダウンロードは本人がAmazon UIで取得。取得したファイルをアプリに指定または許可したダウンロードフォルダから読み込み、内容を検証・紐付け後にDriveへアップロード。

### 2回目以降
初回に許可した非破壊処理は確認ダイアログ不要。次の場合は必ず確認: 初回大量同期、アカウント切替、保存先変更、既存ファイル置換/削除、公式DLブラウザ自動化の初回有効化。

## 状態文言と色の優先順位

- 購入確認済み、購入未確認、対象外（書籍属性）。
- 公式DL可、取得保留、確認待ち、操作待ち（取得属性）。
- Drive同期済み、未保存、アップロード失敗、照合不可（保存属性）。
同一軸の排他的状態と複数軸の併存を認める。色だけで伝えずテキストとアイコンを併記。エラーは次にとれる行動を必ず併記する。

## 非同期UI契約

同期エンジンがイベント（run_started, book_discovered, task_started, task_progress, task_blocked, task_completed, run_completed）を発行し、UIはイベントから表示状態を構築する。UIはアプリケーションのjob状態を書き換えず、許可された「同期開始/キャンセル/リトライ」コマンドだけを送る。
